# Multi-LLM Router — Design Spec
**Date:** 2026-04-09
**Projects:** ReplayMod (primary), ThanosAI (migration target)
**Status:** Approved, ready for implementation

---

## 1. Problem

### ReplayMod
Commentary is generated by a single model (Claude Haiku) with no fallback, no quality measurement, and no learning loop. The 100-sample audit showed:
- Human-ness: 6.2/10
- Redundancy: 3.5/10 (most critical failure — "couldn't carry the load", "the rest of the roster", "went nuclear" overused constantly)
- JSON chain-of-thought leak in ~3% of outputs (test runner issue, not production)
- Hallucination: player nicknames from wrong players (Hand 43: "Book" applied to Randle)
- Deadpan persona dominates (~60% of outputs) — persona rotation not working

### ThanosAI
Router exists (Groq → DeepSeek → Claude fallback) but is a dumb waterfall — no learning, no cross-checking. Grader exists but grades `"[streamed]"` placeholder text, making all score data meaningless.

### Shared goal
Build a self-improving router that gets cheaper over time as free models prove they match Claude quality on specific hand/query types.

## 2. Architecture — Parallel Cross-Check Router (Option A)

```
                    ┌─────────────────────────────────┐
                    │         shared/router/           │
                    │                                  │
  Hand result  ───► │  A (Claude Haiku) ──────────────►│──► ship to user immediately
                    │                                  │
                    │  B (Groq/Llama)  ─┐              │
                    │  C (DeepSeek)    ─┤─ async ─────►│──► D grades all 3
                    │                   │              │    if better line: patch in
                    │  D (Llama judge) ◄┘              │    scores → KV
                    └─────────────────────────────────┘
```

### Every hand
1. **A generates and ships immediately** — same latency as today (~1-2s). User sees commentary instantly.
2. **B + C run in parallel, async** — same prompt, fire-and-forget after A ships.
3. **D grades all 3** against 6 criteria (scores 1-10 each, composite weighted score).
4. **If B or C scores higher than A AND arrives within 1.5s**, the UI patches the commentary silently.
5. **All 3 scores write to KV** regardless of which line wins.

### Every 5th hand (challenger rotation)
- D takes a turn **generating** instead of judging
- D's output is graded by the same D-grader prompt, but run against D's own line — so D self-grades and B+C cross-grade using the same 6-criteria grading prompt (Llama via Groq for all three grading calls, keeping cost zero)
- D's generator score accumulates separately from its judge score
- Data feeds routing decisions over time

### Cost optimization (long-term)
When a free model's rolling 30-day average composite score comes within **0.5 points** of the current primary model for a given context (tier, story type, sport), it gets **promoted to primary** for that context. The displaced model becomes a cross-checker.

Example progression:
```
Month 1:  A=primary always
Month 3:  B promoted to primary on BUST hands (score gap closed)
Month 6:  B primary on BUST+ROOKIE, C primary on STARTER, A reserved for ALL_STAR+
```

## 3. The 6-Criteria Grading Rubric (ReplayMod)

D scores each generated commentary line 1–10 on all 6 criteria:

| # | Criterion | What D checks | Weight |
|---|---|---|---|
| 1 | **Human-ness** | Reads like a real person, not a template | 0.30 |
| 2 | **NBA vibe** | Has personality/opinion — Shaq/Chuck energy, not ESPN.com | 0.20 |
| 3 | **One-message clarity** | Single story, no contradiction, win/loss framing consistent | 0.15 |
| 4 | **Hand accuracy** | Reflects what actually happened to this specific roster | 0.15 |
| 5 | **Non-redundancy** | No overused phrases from the banned list | 0.10 |
| 6 | **Cultural truth** | Nicknames and player facts match the playerCulture.ts DB | 0.10 |

**Composite score** = weighted average of all 6.

**D's grading prompt** receives: the generated line, the hand result data (tier, roster, actual FPs), and a banned-phrases list pulled from recent KV entries. D returns JSON: `{ scores: {...}, composite: number, flags: string[] }`.

## 4. KV Data Model

Each project uses its own separate Upstash Redis instance. Same key schema, different namespace prefix.

```
# Rolling model scores
{ns}:model:{model}:scores              → { total, sum_composite, sum_human, sum_nba, sum_clarity, sum_accuracy, sum_redundancy, sum_cultural }
{ns}:model:{model}:tier:{tier}:scores  → { total, sum_composite }    # per payout tier
{ns}:model:{model}:story:{story}:scores → { total, sum_composite }   # per story type (future)

# Routing decisions (updated when threshold crossed)
{ns}:routing:primary                   → model name (default: "claude-haiku-4-5")
{ns}:routing:primary_by_tier           → JSON { BUST: "groq", ROOKIE: "claude-haiku-4-5", ... }

# Challenger rotation state
{ns}:challenger:counter                → integer 0-4 (increments each hand, resets on 5)
{ns}:challenger:last_model             → model name

# Anti-redundancy memory
{ns}:recent:phrases                    → list, max 20 (lpush + ltrim)
{ns}:recent:tones                      → list, max 10 (lpush + ltrim)
{ns}:recent:stories                    → list, max 10 (lpush + ltrim)

# Grade history (for dashboard/debugging)
{ns}:grades:all                        → list, max 5000 (lpush + ltrim)
{ns}:stats:daily:{date}                → { grades_recorded, sum_composite }
```

`{ns}` = `replaymod` | `thanosai`

## 5. Anti-Redundancy Integration

The banned-phrases list is built from KV at request time and injected into BOTH the generation prompt and the grading prompt.

**Generation side** (`promptBuilder.ts` extension):
```
BANNED (used in last 20 outputs — do NOT use these):
- "couldn't carry the load"
- "the rest of the roster"
- "went nuclear"
- [dynamically pulled from KV]
```

**Grading side** (D's prompt):
```
Non-redundancy score: Check if the line contains any of these recently-overused phrases:
[same list from KV]
If yes: score ≤ 4. If no: score based on overall freshness of phrasing.
```

After each accepted output, the generator logs new notable phrases to KV (lpush + ltrim 20).

## 6. Shared Code Structure

```
shared/
  router/
    llmRouter.ts          # model selection + routing logic (reads KV for primary)
    grader.ts             # criterion-based scoring (configurable rubric per project)
    challengerCycle.ts    # counter logic, rotation schedule
    kvStore.ts            # Upstash read/write abstraction (thin wrapper)
    types.ts              # RouterConfig, GradeResult, ModelScore, etc.
  commentary/             # existing — unchanged
    generateCommentary.ts
    promptBuilder.ts
    types.ts
```

Both projects import from `shared/router/`. Each project passes its own:
- `RouterConfig` (model list, KV namespace, rubric weights)
- `GraderConfig` (criteria definitions, banned-phrases source)
- `KV` client (its own Upstash instance)

## 7. ThanosAI Migration

### Stream-capture fix (prerequisite)
ThanosAI currently grades `"[streamed]"` — all score data is meaningless. Fix: buffer the response, grade async, then stream to client.

```typescript
// api/chat.ts — after generating body stream
const [gradeStream, clientStream] = body.tee()
gradeAsync(gradeStream, message, mode, modelUsed)  // fire-and-forget
return new Response(clientStream, { headers: sseHeaders })
```

### ThanosAI grading rubric (5 criteria, different from ReplayMod)
| # | Criterion | Weight |
|---|---|---|
| 1 | Clarity | 0.25 |
| 2 | Helpfulness | 0.25 |
| 3 | Conciseness | 0.20 |
| 4 | Language match | 0.15 |
| 5 | Overall quality | 0.15 |

### ThanosAI gets
- Challenger rotation (every 5 queries, a free model challenges primary)
- Real grade data (stream-capture fix)
- Cost optimization routing (same threshold: 0.5 composite gap → promote)
- Anti-repetition memory (track recent response patterns per mode)

## 8. Implementation Order

1. **ReplayMod first** — shared/router/ foundation, commentary grader, KV schema, anti-redundancy integration
2. **ReplayMod commentary prompt fixes** — JSON leak prevention, persona rotation enforcement, cultural truth validation
3. **ReplayMod leaderboard feature** — polish the existing LeaderboardScreen component
4. **ThanosAI migration** — stream-capture fix, plug into shared router, activate challenger rotation
5. **Cost routing logic** — threshold detection + automatic primary promotion (once enough grade data exists)

---

## 9. Success Criteria

- Commentary composite score reaches **85% average** (8.5/10) before launch
- Redundancy score improves from 3.5 → **7.0+** within first 500 hands
- ThanosAI grade data becomes real (non-"[streamed]") after migration
- At least one free model promoted to primary for at least one tier within 90 days
- Zero hallucinated nicknames in graded outputs
